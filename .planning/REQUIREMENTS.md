# Requirements: Job Finder

**Defined:** 2026-04-11
**Core Value:** Surface the most relevant job opportunities for the user, deduplicated and AI-ranked, without manual searching.

## v1 Requirements

### Search Configuration

- [ ] **SRCH-01**: User can define search keywords (job title, skills, etc.)
- [ ] **SRCH-02**: User can define target location (city/country)
- [ ] **SRCH-03**: User can filter by experience level (entry / mid / senior / director)
- [ ] **SRCH-04**: User can filter by work mode (onsite / hybrid only — exclude fully remote)
- [ ] **SRCH-05**: User can save search configuration and reuse it across scrape runs
- [ ] **SRCH-06**: User can trigger a manual scrape run from the UI

### User Profile

- [ ] **PROF-01**: User can input their LinkedIn profile URL
- [ ] **PROF-02**: User can input skills, current/target job title, and years of experience manually
- [ ] **PROF-03**: AI (Groq) analyzes the profile and returns improvement recommendations
- [ ] **PROF-04**: Profile is persisted locally and pre-filled on subsequent visits

### Job Scraping & Storage

- [ ] **SCRP-01**: App scrapes jobs from LinkedIn, Indeed, and Glassdoor via JobSpy
- [ ] **SCRP-02**: Jobs are deduplicated across sources (same job shown once, hash on title + company + location)
- [ ] **SCRP-03**: Scraped jobs are persisted in local SQLite database with WAL mode enabled
- [ ] **SCRP-04**: Each job stores: title, company, location, description, source, apply URL, scraped date

### Job List & AI Scoring

- [ ] **JOBS-01**: User can browse all scraped jobs in a paginated/scrollable list
- [ ] **JOBS-02**: Each job displays an AI fit score (0–100) generated by Groq against user profile
- [ ] **JOBS-03**: Fit score includes a brief AI summary of why the job is or isn't a good match
- [ ] **JOBS-04**: Jobs without listed salary show a Groq-estimated typical salary range (labeled "Estimated") based on job title + country
- [ ] **JOBS-05**: Jobs with listed salary display the actual salary range
- [ ] **JOBS-06**: User can set per-job status: Saved / Applied / Interviewing / Offer / Rejected
- [ ] **JOBS-07**: User can filter jobs by status, fit score range, and company

### Watch Rules & Notifications

- [ ] **WTCH-01**: User can create a watch rule matching by company name (exact)
- [ ] **WTCH-02**: User can create a watch rule matching by role keyword (title contains)
- [ ] **WTCH-03**: User can create a watch rule matching by sector/industry tag
- [ ] **WTCH-04**: After each scrape, newly matched jobs are flagged as "watched matches"
- [ ] **WTCH-05**: Nav badge shows count of unread watch matches
- [ ] **WTCH-06**: User can view all watch matches in a dedicated section
- [ ] **WTCH-07**: User can manage (add / delete) watch rules from the UI

### Web UI

- [ ] **UI-01**: App runs as a local web server accessible in the browser
- [ ] **UI-02**: UI uses Jinja2 templates + HTMX for dynamic updates (no JS build toolchain)
- [ ] **UI-03**: Navigation between: Jobs, Profile, Search Config, Watch Rules
- [ ] **UI-04**: Working app state visible in browser at the end of each phase

## v2 Requirements

### Enhancements

- **V2-01**: Automatic scheduled scraping (APScheduler, e.g. every 4 hours)
- **V2-02**: Proxy rotation to bypass LinkedIn 250-job cap
- **V2-03**: Export jobs to CSV
- **V2-04**: Full-text search on job descriptions (SQLite FTS5)
- **V2-05**: Salary trend chart across scraped jobs
- **V2-06**: LinkedIn profile data scraping (pull skills/experience from profile URL)
- **V2-07**: Kanban board view for job status tracking

## Out of Scope

| Feature | Reason |
|---------|--------|
| Email / desktop push notifications | POC scope — in-app only is sufficient |
| Multi-user / auth | Personal use only |
| Auto-applying to jobs | Out of scope by design |
| Uploading resume PDF/DOCX | Manual input sufficient for POC |
| Fully remote jobs | User explicitly excluded these |
| Part-time / contract / internship jobs | User wants full-time only |
| Kanban board | Status dropdown achieves same goal with 1/10th the complexity |
